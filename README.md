# IncrementForge · 增量工坊

在浏览器里做增量（incremental / idle）游戏。左边写数据，右边立刻能玩，点一下**打包**就得到一个可以双击打开的单文件 HTML —— 发给谁，谁都能玩，不需要服务器、不需要联网。

> 面向**游戏作者**。你不需要会写代码：价格曲线、产出公式、升级条件全部写在表达式框里，编辑器会实时告诉你写得对不对。

---

## 特性

- **大数运算**：数值层基于分层指数表示（`break_eternity`），`1e1e10`、`10 ↑↑ 1e15` 这类幂塔量级不会溢出成 `Infinity`。
- **表达式沙箱**：自研词法/语法分析与闭包编译器，没有 `eval`，没有 `new Function`，危险的标识符在解析期就被拒绝。
- **五类条目**：资源、生成器、升级、页面、设置，覆盖增量游戏的全部基本构件。
- **数据即代码**：价格、产出、条件、效果都能写成表达式，并且能在运行时被其它条目引用和改写 —— 这是做深层联动玩法的关键。
- **实时预览**：右侧 iframe 沙箱里就是真游戏，编辑时热更新，不用反复打包。
- **模拟工具栏**：手机/平板/自适应、暂停、时间倍速、一键解锁全部，调试后期内容很省事。
- **单文件打包**：产出**一个** `.html`，运行时全部内联。存进度走 `localStorage`，双击就能玩。
- **内置素材**：38 个图标、9 套主题（编辑器 3 + 页面 3 + 条目 3），都支持自己上传替换。
- **完整诊断**：预览区常驻面板 —— 错误码明细、tick 耗时、缓存命中率、打包体积、孤儿动态条目、降级建议。

## 快速开始

需要 **Node.js ≥ 20.11** 和 **pnpm 10**（仓库用 `packageManager` 字段锁定版本）。

```bash
pnpm install
pnpm dev
```

浏览器打开 <http://localhost:5173>。首次启动会载入一个可玩的示例项目（矿机 → 点击器 → 双倍产量升级 → 动态创建条目），可以直接上手改。

想从零开始就点标题栏的**新建**。

### 打包一个游戏

编辑器里点**打包**（或按 `Ctrl+P`），浏览器会下载一个 `<项目名>.html`。这个文件：

- 双击用浏览器打开即可游玩；
- 离线可用，不请求任何外部资源；
- 进度存在浏览器的 `localStorage`，键由项目指纹派生 —— 同一个项目重新打包后仍读同一份进度。

命令行等价物：

```bash
pnpm --filter @iforge/build run pack -- <project.json> --out game.html --sizes
```

校验不通过会以非 0 退出码结束，并逐条列出问题出在哪个字段。

## 编辑器怎么用

四区布局：顶部标题栏、左侧功能区、中间工作区、右侧预览区。

### 顶部标题栏

新建 / 保存 / 导入 / 导出 / 撤销 / 重做 / 打包。有未保存改动时项目名旁会显示一个圆点。打包按钮在预览就绪前是灰的。

### 左侧功能区

资源 / 生成器 / 升级 / 页面 / 设置。切换工作区不进历史栈，也不会改动项目数据。

### 中间工作区

四类工作区结构一致：左侧是条目列表（图标 + 名称 + 排序/复制/删除），右侧是当前条目的表单。

| 工作区 | 关键字段 |
| --- | --- |
| **资源** | 初始数量、数量上限、游戏可见 |
| **生成器** | 购买价格、产出资源、批量购买、是否点击器 |
| **升级** | 购买条件、购买价格、每秒生效、升级效果 |
| **页面** | 页面主题、布局列数、页面条目及各自主题 |
| **设置** | 项目信息、只读元数据、游戏默认设置 |

多数字段右侧都有一个 `fx` 按钮 —— 点它把输入切成**表达式模式**，里面可以写 `gen.g1.bought * 10` 这样的公式。表达式模式下有实时校验：写错了当场标红并给出错误码。

### 右侧预览区

上方是模拟设置栏（**不属于游戏内容，不会进打包产物**）：设备尺寸三选一、暂停/继续/重新开始、时间倍速下拉、一键解锁全部。

中间是游戏本体：顶部标题、数据仪表盘、资源与条目卡片、底部导航。编辑时改动会热更新推送到这里。

下方常驻诊断面板：诊断（错误明细与计数）、性能（tick 耗时、求值次数、缓存命中率、格式化次数、预算耗尽标记）、孤儿（动态条目归属页面失效后的清单，可一键丢弃）、打包（字节数、gzip、指纹）、降级建议。

## 表达式速查

### 字面量与运算符

```
123        1.5        1e10        1e1e10        -2.5e-3        Infinity
```

运算符按优先级从低到高：`||` → `&&` → `== != === !==` → `< <= > >=` → `+ -` → `* / %` → `^ **`（右结合）。还有一元 `- + !` 和复合赋值 `= += -= *= /=`。

`Infinity` 是保留字面量，代表"无上限"，写 `max: "Infinity"` 就表示不钳制。

> 列表字面量 `[...]` 和对象字面量 `{...}` 在 V1.0 里是**语法保留但不可写**的 —— 它们只在 `create()` 的 spec 实参位置合法，其它地方写会报 `E_LITERAL_NOT_ALLOWED`。请用 `set()` 去改列表里的具体位置。

### 引用路径

```
res.<id>.amount          资源数量（.owned 是它的读写别名）
gen.<id>.bought          已购买数量（影响价格）
gen.<id>.owned           拥有数量（已买 + 其它条目产出的）
gen.<id>.perSec          每秒产出合计（只读）
up.<id>.bought           升级已购买数量
page.<id>.visible        页面可见性
```

### 内置函数

| 分类 | 函数 |
| --- | --- |
| 基础 | `min` `max` `clamp` `lerp` `abs` `sign` |
| 取整 | `floor` `ceil` `round` `trunc` |
| 对数指数 | `sqrt` `ln` `log10` `log` `pow` `exp` |
| 分支 | `if`（三个实参都先求值，没有短路） |
| 随机 | `rand` `randInt` `randChance` |
| 副作用 | `set` `create` `destroy` |
| 动态条目 | `has` `count` |

### 权限矩阵

表达式按用途分成五个上下文，能用什么是**编译期**判定的，写错当场报错：

| 上下文 | 用于 | 随机函数 | `set`/`create`/`destroy` |
| --- | --- | --- | --- |
| `field` | 初始数量、上限、批量购买等字段 | ✅ | ❌ |
| `price` | 购买价格 | ❌ | ❌ |
| `production` | 产出数量 | ✅ | ❌ |
| `condition` | 购买条件、效果前提 | ✅ | ❌ |
| `effect` | 效果内容 | ✅ | ✅ |

随机函数在价格上下文被禁用（否则同一件商品每次刷新价格都不同），`create`/`destroy`/`set` 只在 `effect` 上下文可用。离线结算另有 `offline` 上下文：不触发随机、不触发副作用。

### 动态创建条目

`create()` 可以在游戏运行中凭空造出新条目，它不会出现在编辑器里，只写进存档：

```
create("generator", {
  page: "p2",
  name: "临时发电机",
  costs: [{ materialId: "r1", amount: "100" }],
  produces: [{ materialId: "r1", amount: "5" }]
})
```

`kind` 只能是 `generator` 或 `upgrade`，`page` 必填，一个条目只能属于一个页面。

## 打包与存档

### 项目文件

`.json`，Zod schema 校验，跨版本有迁移器。导入导出走这个格式，未知字段会保留。

### 游戏存档

存档与项目文件是两回事：**存档只进存档，不进项目文件**。所有运行期的赋值（包括表达式文本本身）都持久化在存档里，点"重新开始"才回到项目初始状态。

- 编辑器预览：存档在 IndexedDB 里，iframe 沙箱碰不到 `localStorage`。
- 打包产物：存档在 `localStorage["incrementforge.save.<projectId>"]`。

游戏内设置页提供导出/导入存档，以及重新开始。

### 打包前的 7 条校验

表达式能否编译、静态依赖有没有环、赋值目标有没有权限、有没有悬空引用、页面是否唯一、`create()` 的键是否在白名单内、资产与设置是否合法。任何一条不过就弹问题清单，**逐条标出字段位置**。

## 项目结构

```
apps/editor/        编辑器应用（React 19 + Vite）：四区布局、四类工作区、撤销重做、项目生命周期、预览宿主
apps/runtime-shell/ 游戏运行时（React 19 + Vite）：主循环 + postMessage 桥 + 游戏视图（预览与打包共用）
packages/num/       数值层：Decimal 封装、饱和语义、显示格式化、错误码
packages/expr/      表达式沙箱：词法/Pratt 解析/静态校验/闭包编译/求值器/副作用
packages/model/     数据模型：Zod Schema、默认值、id 与排序、跨条目校验、示例项目
packages/runtime/   游戏运行时：帧时钟/tick 时序/产出/购买/批量求解/升级效果/动态条目/存档/离线
                    ＋ 宿主协议 / 视图模型 / 热更新补丁（均无 DOM 依赖）
packages/i18n/      国际化：t() + LocaleRegistry + zh-CN 文案
packages/ui-kit/    主题令牌、内置主题/图标注册表、SVG/CSS 安全过滤
packages/persist/   IndexedDB 仓储与项目导入导出
packages/build/     单文件打包：打包前校验、产物指纹、HTML 模板、esbuild 编译、CLI
e2e/                Playwright 用例：编辑器全流程 + file:// 下的打包产物与游玩链路
tools/              docs:check（文档交叉校验）
docs/               PRD.md（产品需求）/ TECH_DESIGN.md（技术方案）/ ADR/（架构决策记录）
```

依赖方向严格单向：`num ← expr ← model ← runtime ← (persist | build)`。`packages/*` 不碰 DOM（`persist` 和 `ui-kit` 除外，它们分别需要 IndexedDB 和 DOMParser）。两个 app 之间也不互相 import —— `editor` 只在**构建期**消费 `runtime-shell` 打好的产物，因此"预览能跑"和"产物能跑"不可能分叉。

## 开发

```bash
pnpm install       # 安装依赖
pnpm dev           # 启动编辑器（Vite dev server，http://localhost:5173）
pnpm verify        # 门禁：typecheck + test + docs:check + lint
pnpm typecheck     # tsc --noEmit（packages/* + apps/*）
pnpm test          # vitest run（各包 + runtime-shell + editor + editor-node 四类 project）
pnpm docs:check    # 文档一致性校验
pnpm lint          # eslint + prettier --check
pnpm build         # 构建编辑器产物（跑 e2e 前必须先 build）
pnpm e2e           # Playwright：editor + packaged-game 两个 project
pnpm e2e:ui        # 同上，带 UI 模式
pnpm verify:e2e    # build + e2e
pnpm bench         # 性能基准（tick 耗时、缓存命中率）
```

`pnpm verify` 是提交前的合并门禁入口。E2E 分两个 project：`editor` 在真浏览器里改数据 → 打包 → 下载；`packaged-game` 把产物当**本地文件**（`file://`）打开 —— 用 `file://` 而不是 HTTP 是刻意的，残留的外部引用只有在 `file://` 下才暴露。

## 已知限制

- **界面仅中文**。多语言框架（`LocaleRegistry`）已经就位，文案集中在 `packages/i18n`，加语言不需要改运行时。
- **单项目、单存档**。多项目与多存档的管理框架预留了位置，V1.0 没有实现。
- **离线收益是近似结算**。按速率分段积分，误差方向取决于速率的变化趋势（界面会标注）。建议把产出速率写成非递减形式。
- **离线时不触发自动购买与"每秒生效"**，所以离线收益低于在线收益。
- **浏览器侧的 gzip 体积拿不到**（没有 zlib），打包面板会显示"未知"而不是让打包失败。
- 数值上界是 `10 ↑↑ 1e15`，超过即饱和。
